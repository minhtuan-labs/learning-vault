# Engine Permission Policy — v10.23

> Filename kept as `OPENCODE_PERMISSION_POLICY.md` for backward
> compatibility — content now covers both engines (OpenCode + Claude
> Code) as of v10.12, plus the v10.19 PATH guard and v10.23 PreToolUse
> hook for Orchestrator lane enforcement.

## Purpose

This template uses tmux panes as the real execution boundary. The
engine's built-in `Task` / `general-task` subagent must be disabled
so that work is routed to real panes (each with its own model and
audit trail) instead of running inside one process as a virtual
subagent.

Each engine has its own policy file:

| Engine | Policy file | Generated by |
|---|---|---|
| OpenCode | `.opencode/config.json` + `opencode.json` (root mirror) | `scripts/start_agents_tmux.sh` (regenerated each session) |
| Claude Code | `.claude/settings.json` | `scripts/start_agents_tmux.sh` (regenerated each session) |

Both are written inline by `start_agents_tmux.sh` so the policy is
always in lockstep with the framework version. Editing them by hand
will be overwritten the next time you start the session.

## OpenCode policy

`.opencode/config.json` (auto-generated):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": "allow",
    "edit": "allow",
    "webfetch": "allow"
  },
  "agent": {
    "build": { "tools": { "task": false, "general-task": false } },
    "plan":  { "tools": { "task": false, "general-task": false } }
  }
}
```

Why these settings:

- `permission.bash = "allow"` — workers call `route_to_pane.sh`,
  `ask_orchestrator.sh`, `docker compose up`, `pytest`, etc.
- `permission.edit = "allow"` — workers write to their lane.
- `permission.webfetch = "allow"` — only for clearly-bounded research
  (e.g. checking a library's docs while writing BE_PLAN.md).
- `agent.build.tools.task = false` and `agent.plan.tools.task = false`
  — the framework requires real shell handoffs, not internal subagent
  dispatch. This is the correct schema for OpenCode (the older
  v9-style `permission.task` is silently ignored — see VERSION.md).

A mirror is also written to `opencode.json` at project root for forks
that prefer the root-level filename.

## Claude Code policy

### Why this policy is broader than OpenCode's

Claude Code has a stricter default permission model than OpenCode.
Even when you allow an outer command like `Bash(bash:*)`, Claude
**separately checks every command inside `$(...)` substitutions**.
The framework's scripts use command substitution extensively
(`PANE_ID=$(grep ...)`, `TS=$(date ...)`, `sz=$(wc -c < "$f")`, …),
so without an explicit allow list Claude would ask permission for
every `grep` / `cut` / `date` / `wc` / `find` inside every routing
call — completely breaking the auto-flow.

OpenCode's `"permission": { "bash": "allow" }` is a single global
allow that covers substitutions transparently. Claude needs the full
list of utility commands explicitly listed.

The policy below covers every utility used inside `$(...)` in the
shipped scripts plus the engine binaries themselves.

### The policy

`.claude/settings.json` (auto-generated):

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      // Engine + framework binaries
      "Bash(bash:*)", "Bash(tmux:*)", "Bash(git:*)",
      "Bash(opencode:*)", "Bash(claude:*)", "Bash(docker:*)",
      "Bash(curl:*)", "Bash(npm:*)", "Bash(pip:*)",
      "Bash(pytest:*)", "Bash(node:*)",
      // Utility commands used INSIDE $(...) substitutions throughout
      // scripts/*.sh — without these, Claude prompts for each one.
      "Bash(grep:*)", "Bash(sed:*)", "Bash(awk:*)", "Bash(cut:*)",
      "Bash(find:*)", "Bash(wc:*)", "Bash(date:*)", "Bash(pwd:*)",
      "Bash(ls:*)", "Bash(cat:*)", "Bash(echo:*)", "Bash(printf:*)",
      "Bash(basename:*)", "Bash(dirname:*)", "Bash(head:*)", "Bash(tail:*)",
      "Bash(mkdir:*)", "Bash(rm:*)", "Bash(cp:*)", "Bash(mv:*)",
      "Bash(chmod:*)", "Bash(stat:*)", "Bash(test:*)",
      "Bash(true:*)", "Bash(false:*)", "Bash(:*)",
      "Bash(source:*)", "Bash(.:*)",
      // File / web ops
      "Read", "Write", "Edit", "WebFetch"
    ],
    "deny": [ "Task" ]
  }
}
```

Why these settings:

- `permissions.allow` — explicit allow list keeps Claude Code's
  prompts to a minimum. Each `Bash(<cmd>:*)` entry permits a specific
  command family.
- **Utility commands for command substitution** — Claude inspects every
  command inside `$(...)` separately, so we explicitly allow the
  POSIX/coreutils that scripts use (`grep`, `cut`, `awk`, `date`, `pwd`,
  `wc`, `find`, …). Without these, the Orchestrator would prompt you
  to confirm every substitution in every routing call.
- `permissions.deny: ["Task"]` — disables Claude Code's built-in
  Task tool (subagent dispatcher). Same intent as the OpenCode
  `agent.<mode>.tools.task = false`.
- `Read / Write / Edit / WebFetch` — file ops + bounded web access.

### If Claude still asks for a substitution

When you see "may I run `<cmd>`?" prompts for a command not in the
allow list, the safest fix is to **add it to the JSON in this file's
canonical location** — but the file is auto-generated by
`scripts/start_agents_tmux.sh`. To make the change permanent across
session restarts, edit the heredoc inside that script (look for
`case "$ENGINE" in claude)` block) and re-run start.

For one-off bypass, choose "Always allow this command" in the prompt —
Claude Code stores it in `~/.claude/settings.local.json`.

### v10.23 — PreToolUse hook for Orchestrator lane discipline

`.claude/settings.json` now also registers a hook on `Write`/`Edit`
tool calls:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit|NotebookEdit",
        "hooks": [
          {
            "type": "command",
            "command": "bash scripts/guards/check_file_lane.sh"
          }
        ]
      }
    ]
  }
}
```

The hook script:

- Reads `$AGENT_NAME`. **Exits 0 immediately for any non-Orchestrator
  pane** — workers (BE/FE/QA/DELIVERY/etc.) are unaffected.
- For the Orchestrator pane, parses the target `file_path` from the
  tool's JSON input on stdin.
- Allow-list short-circuit for files Orches IS permitted to edit:
  `TASK.md`, `PRODUCT_IDEA.md`, `memory/_PROJECT_STATE.md`,
  `memory/ORCHESTRATOR.md`, runtime `.pane_*` / `.agent_*` artifacts.
- Block-list match (`backend/*` → BE, `frontend/*` → FE,
  `docs/qa/*` → QA, etc.) → exit 2 with BLOCKED message containing
  the correct `route_to_pane.sh` invocation.

This closes the v10.19 loophole where Claude's Write/Edit tools
bypassed the PATH guard (which only intercepts shell commands).
Single settings.json, all 9 panes share it — per-pane behaviour comes
from `$AGENT_NAME` check inside the hook.

OpenCode is unaffected (different tool model, no equivalent hook
mechanism). The PATH guard (v10.19) covers both engines for shell
commands.

## Route-to-pane rule (unchanged for either engine)

Use:

```bash
bash scripts/route_to_pane.sh PM "..."
bash scripts/delegate_phase.sh discovery
```

If you suspect a routing event didn't actually fire, run:

```bash
bash scripts/verify_routing.sh
```

This reads `.pane_tasks/` + `.pane_logs/_routing_receipts.log` to
prove a real shell command happened (vs the Orchestrator only
describing routing in chat).

```bash
bash scripts/check_models.sh opencode    # dynamic — calls `opencode models`

```
