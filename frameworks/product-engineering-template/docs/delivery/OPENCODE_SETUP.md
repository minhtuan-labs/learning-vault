# Engine Setup — v10.12

The framework supports two engines as of v10.12. Pick at session start:

```bash
bash scripts/start_agents_tmux.sh <project> --engine opencode   # default
bash scripts/start_agents_tmux.sh <project> --engine claude
```

The engine choice is persisted in `.agent_session` so every later
script picks the right CLI automatically.

## Engine A — OpenCode (default)

### Config file

`.opencode/config.json` (auto-generated by `start_agents_tmux.sh`):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": { "bash": "allow", "edit": "allow", "webfetch": "allow" },
  "agent": {
    "build": { "tools": { "task": false, "general-task": false } },
    "plan":  { "tools": { "task": false, "general-task": false } }
  }
}
```

A mirror is also written to `opencode.json` for forks that prefer the
root-level filename.

### Worker invocation

```bash
OPENCODE_CONFIG=<project>/.opencode/config.json \
  opencode run --model <target_pane_model> \
    "Execute the routed pane task ..."
```

### Model list

Configured at `config/engines/opencode.env`. Default models (v10.12):

## Engine B — Claude Code

### Config file

`.claude/settings.json` (auto-generated):

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "Bash(bash:*)", "Bash(tmux:*)", "Bash(git:*)",
      "Bash(opencode:*)", "Bash(claude:*)", "Bash(docker:*)",
      "Bash(curl:*)", "Bash(npm:*)", "Bash(pip:*)",
      "Bash(pytest:*)", "Bash(node:*)",
      "Read", "Write", "Edit", "WebFetch"
    ],
    "deny": [ "Task" ]
  }
}
```

`AGENTS.md` is also auto-copied to `CLAUDE.md` because Claude Code's
auto-context loader prefers that filename.

### Worker invocation

```bash
claude --print --model <target_pane_model> \
    "Execute the routed pane task ..."
```

### Model list

Configured at `config/engines/claude.env`. Default mapping uses
Claude's 3-tier model lineup:

```text
ORCHESTRATOR  claude-sonnet-4-6
PM            claude-haiku-4-5
SA            claude-opus-4-6
BA            claude-haiku-4-5
UX            claude-haiku-4-5
BE            claude-opus-4-6
FE            claude-sonnet-4-6
QA            claude-haiku-4-5
DELIVERY      claude-haiku-4-5
```

## Validate models for either engine

```bash
bash scripts/check_models.sh opencode
bash scripts/check_models.sh claude
```

OpenCode uses dynamic validation (calls `opencode models`).
Claude Code uses a static whitelist (`ENGINE_KNOWN_MODELS` in
`config/engines/claude.env`) because there is no `claude models`
subcommand.

## When to pick which engine

| You want to … | Pick |
|---|---|
| Mix many cheap providers, fine-grained cost optimisation | `opencode` |
| Single Anthropic API key, fewest moving parts | `claude` |
| Newbie / experimenting with free tiers | `opencode` |
| Production-ish, single-vendor consistency | `claude` |

You can also switch engines between sessions — `memory/` is committed
to git, so the team's state persists across engine changes.
